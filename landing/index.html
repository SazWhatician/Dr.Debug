DR. DEBUG FAQ

Installation, Docker bridge setup, and honest answers about what Dr. Debug actually does.

01 Download the ZIP

Click the Download Chrome Extension button above to get dr-debug-extension.zip.

02 Extract the archive

Unzip it to any folder on your machine. You'll see a folder with manifest.json, content.js, and related files inside.

03 Open Chrome Extensions

Navigate to chrome://extensions in your browser. Toggle on Developer mode (top-right corner).

04 Load unpacked

Click "Load unpacked" and select the extracted folder. The 🩺 Dr. Debug panel will appear inside Chrome DevTools (press F12).

01 Make sure Docker is running

Dr. Debug's bridge reads container logs from Docker on your machine. Start Docker Desktop or ensure the Docker daemon is active.

02 Run the bridge launcher

Double-click start-docker-bridge.bat (Windows) or run ./start-docker-bridge.sh (Mac/Linux) from the extracted folder. Alternatively, run:

$ npx -y @dr-debug/mcp

03 Done — container logs stream live

The bridge runs read-only Docker commands (docker ps, docker logs -f) and streams container stdout/stderr to Dr. Debug over local SSE on port 9229. It never writes to Docker or executes commands inside containers.

Dr. Debug captures live browser telemetry — errors, network failures, console logs, stack traces, and memory snapshots — and serializes it into a structured Markdown incident report. You copy this report with a single click and paste it into Antigravity's chat. This gives the AI agent rich, deterministic runtime context instead of vague descriptions or screenshots, so it can locate and fix the exact lines in your codebase. It's a clipboard export bridge, not a direct API integration.

Same approach as Antigravity: Dr. Debug's one-click "Copy AI Brief" button generates a structured 🚨 Incident Report for AI Assistants (Claude Code / Antigravity) containing causal chains, HTTP payloads, stack traces, and timeline data. Paste it into Claude Code's terminal and it has all the context to debug your issue without guessing. There is no live API connection — it's a formatted export optimized for AI coding assistants to parse.

No. Dr. Debug is 100% local-first. All telemetry — console logs, network bodies, memory footprints, Docker container logs — stays inside your browser session and your local machine. Zero tracking, zero analytics, zero cloud servers contacted. The Docker bridge also runs entirely on localhost.
